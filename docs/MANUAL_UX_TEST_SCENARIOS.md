# 수동 UX 테스트 시나리오 (Agentic RAG 대시보드)

브라우저에서 `http://<호스트>:<포트>/` 접속. 사전에 `python scripts/check_env_gates.py --base-url ...` 로 게이트 통과 확인 권장.

## 1. 기본 채팅

1. 새 대화를 시작하고 자연어로 질문을 입력한다.
2. 응답이 스트리밍되며, 진행 중 `[n] … 조회 중…` 형태의 **도구 진행 표시**가 나타나는지 확인한다.
3. 최종 답변에 **요약·목록·분석** 중 하나가 일관된 형태로 표시되는지 확인한다.

## 2. 멀티턴·맥락

1. 첫 메시지에서 특정 호스트나 지표를 묻는다.
2. 후속 메시지에서 **대명사**(“그 서버”, “거기”)만으로 이어질 때, 이전 맥락이 반영되는지 확인한다.
3. **세션 히스토리** 사이드바에서 동일 세션이 유지되는지 확인한다.

## 3. 재문의(clarify)

1. 모호한 질문(호스트명 불명확, 기간 없음 등)을 보낸다.
2. 시스템이 보완을 요청하거나 후속 질문을 하는 경우, **clarify** 응답 후 보완 답을 이어 붙여 재시도할 수 있는지 확인한다(해당 UI가 노출되는 경우).

## 4. 소스·도구 추적

1. 응답 후 **소스/출처** 영역에 Agent `tool_trace` 기반 항목이 표시되는지 확인한다. 소스가 비어 있으면 안내 문구가 “Agent 응답은 도구 실행 이력…”을 포함하는지 확인한다.
2. 데이터가 많을 때 **절삭(truncated_notice)** 이 답변 상단 노란 박스로 표시되는지 확인한다(목록·일반·분석 등 공통).

## 5. 모델 전환

1. UI에서 사용 가능한 다른 LLM 모델을 선택해 동일 질문을 보낸다.
2. 응답 시간·도구 선택 차이를 기록한다(Ollama는 초기 지연 가능).

## 6. 오류·복구

1. 의도적으로 존재하지 않는 호스트만 지정해 질문한다.
2. “찾을 수 없음” 또는 합리적인 안내가 나오는지 확인한다.
3. 네트워크/타임아웃 후 **새로고침 없이** 재질문이 가능한지 확인한다.

## 7. 검색 전용 API와의 대조(선택)

1. 동일 문장을 `POST /api/search` 로 보내 벡터 검색 결과만 확인한다.
2. 채팅(`/api/chat`) 응답과 비교해 **라이브 SQL 도구**가 추가로 동작했는지 사용자 관점에서 구분한다.
